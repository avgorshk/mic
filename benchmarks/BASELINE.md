# Benchmark baseline

The machine's performance snapshot BEFORE any microarchitecture work on
top of the hardware-faithful timing model. Generated by
`python benchmarks/run_bench.py` — the suite compiles each MICC program
with the current toolchain, runs it on the simulator, and verifies the
checksum result. Cycle counts are logical microcode cycles
(deterministic — no host timing).

Baseline commit: `0f1d1f4` (dispatch-timing model fix: JMPC sees the
pre-edge MBR, WIDE takes 2 cycles). All 11 results verified, coverage
21/21 opcodes.

Retired: the earlier numbers captured at `0da40c7`
(10,138,315 / 15,447,389) measured the same-edge-dispatch artifact and
are no longer a valid reference.

Time unit: 1 simulator cycle = 3 micro-clocks, so this baseline is
30,425,772 / 46,352,994 micro-clocks.

How to use it: after any microarchitecture change, rebuild micsim, rerun
the suite, and diff against this file. The programs themselves must stay
unchanged (that is the point — only the machine gets faster). Current
numbers are tracked in the README's micro-architecture versions table.
